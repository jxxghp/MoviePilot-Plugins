# Agent Tokens 管理

按 `(priority, name)` 选择启用、连接配置完整且额度未耗尽的供应商。

## 连续失败自动冷却（1.2.0）

在供应商的新增/编辑窗口中为每条记录单独启用「连续失败自动冷却」。默认关闭，升级后原配置保持原有选号行为。

- 连续失败次数：默认 3 次。按宿主 `AgentTokensUsage` 事件的执行结果计数，包含 429、额度不足等上游错误，也包含其他执行失败；用户取消不推进失败计数。一次成功会清零连续失败次数。
- 初始冷却时长：默认 60 秒。达到阈值后，后续 Agent 轮次跳过该记录，按优先级使用其他可用记录。
- 指数退避：默认关闭。开启后，冷却到期再次达到失败阈值时，时长按上一轮翻倍；一次成功会重置退避。
- 冷却时长上限：默认 3600 秒，固定冷却和指数退避均受此上限约束。

冷却状态持久化保存在插件用量记录中，插件重载或进程重启不会丢失。到期自动恢复参与选号；已经在途的请求成功也会清除冷却，其他在途失败不会延长当前冷却。停用该策略后忽略该记录已有的冷却。

「用量」页显示冷却原因及剩余秒数，状态接口返回 `cooling_down`、`cooldown_until`（Unix 秒）、`cooldown_remaining_seconds`、`cooldown_reason` 和 `consecutive_failures`。刷新可重新获取最新状态，已载入的冷却会在页面倒计时到期后显示可用。触发冷却和成功清除冷却均记录插件日志。重置该供应商用量也会清除其冷却及退避状态。

此策略影响后续轮次的选号，不会在同一次执行中重新运行任务。所有插件记录均不可用时，仍由宿主回落到系统 LLM 配置；如系统配置指向同一个上游，仍可能遇到相同错误。插件记录被显式指定且不允许回退时，保留原有不可用返回约定。

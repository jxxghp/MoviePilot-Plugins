# QQ消息通知（NapCat）

通过 [NapCat](https://github.com/NapNeko/NapCatQQ)（OneBot11 实现）完整接管 MoviePilot 的 QQ 渠道：把 MoviePilot 的全部消息通知推送到好友私聊或群聊，同时接收 QQ 消息作为远程命令控制 MoviePilot，形成「通知下发 + 命令上行」的双向闭环。

插件适用于 MoviePilot V3（`system_version >= 3.0.0`）。

## 功能

| 功能 | 说明 |
| --- | --- |
| 全量通知转发 | 接管 MoviePilot 消息通知，支持私聊与群聊广播 |
| 消息类型过滤 | 按消息类型（订阅、下载、整理、刮削等）选择性推送，私聊与群聊可分别配置 |
| 定向通知 | 与 MoviePilot 用户通知设置联动，命中 `qq_userid` / `qq_openid`（私聊）与 `qq_group_openid` / `qq_group`（群聊）目标键时定向推送 |
| 图片消息 | 通知携带图片时自动以图片消息段发送 |
| @全体成员 | 群聊广播可开启 @全体成员 |
| 远程命令 | 接收 QQ 私聊/群聊消息，转发给 MoviePilot 消息链执行搜索、订阅、下载等交互命令 |
| 群聊回复回原群 | 群聊发起的命令，回复回到原群并 @ 发起者，不落入私聊 |
| @ 激活机制 | 配置机器人 QQ 后，群聊命令首次需 @ 机器人激活，会话过期时间内无需重复 @ |
| 候选列表转发 | 搜索/下载候选列表（媒体、种子）以文本形式回复给发起交互的 QQ 用户，支持数字选择 |
| 上报鉴权 | 支持 OneBot11 标准 `x-signature` HMAC-SHA1 签名、Bearer/裸 Token 请求头与 URL 参数三种校验方式 |

## 工作原理

MoviePilot 的通知分发有两条路径，插件分别接管，互斥分区避免重复发送：

1. **广播通知**：无指定渠道、无 QQ 定向目标的消息通知，通过 `NoticeMessage` 事件广播路径转发给配置的全部私聊/群聊目标，并按消息类型过滤。
2. **模块分发**：插件声明 `post_message`、`post_medias_message`、`post_torrents_message` 模块方法，接管 `channel=QQ` 的定向消息（交互回复）与携带 QQ 目标键的按用户路由通知，以及媒体/种子候选列表消息。

命令的识别与执行由 MoviePilot 消息链（`MessageChain`）完成，插件只负责消息转发。

## 前置条件

- 已部署可用的 MoviePilot V3 实例。
- 已部署 [NapCat](https://github.com/NapNeko/NapCatQQ)（推荐 Docker 部署），并登录一个机器人 QQ 号。
- MoviePilot 与 NapCat 之间网络可达。

## 快速开始

### 第 1 步：部署并配置 NapCat

1. 部署 NapCat，登录机器人 QQ。
2. 在 NapCat 中开启 **HTTP 服务器**，记录服务地址（如 `http://napcat:3000`）与 AccessToken（可选，建议设置）。
3. 在 NapCat 中配置 **HTTP 客户端**：
   - 上报地址填写 `http://<MoviePilot地址>/api/v1/plugin/NapCatMsg/report`
   - 上报方式选择 POST
   - Token 填写一个自定义值（可选，建议设置），与插件「上报令牌」保持一致。

### 第 2 步：安装插件

1. 在 MoviePilot 「设定 → 插件」中，将本插件仓库加入插件市场：
   `https://github.com/gy520187/MoviePilot-Plugins`
2. 在插件市场搜索「QQ消息通知」或「NapCat」，点击安装。
3. 打开插件配置页，开启「启用插件」。

### 第 3 步：填写通知目标并测试

1. 在「NapCat服务地址」填写 NapCat HTTP 服务地址（如 `http://napcat:3000`）。
2. 在「QQ号（私聊）」或「群号（群聊）」填写接收通知的目标，多个用英文逗号分隔。
3. 开启「测试插件（立即运行）」，保存配置。
4. 机器人应收到一条「QQ消息通知测试」消息，收到即代表 MoviePilot 与 NapCat 对接成功。

## 使用指南

### 接收消息通知

- **私聊通知**：在「QQ号（私聊）」填写接收通知的 QQ 号。所有 MoviePilot 广播通知会发送到该 QQ 的私聊会话。
- **群聊通知**：在「群号（群聊）」填写接收通知的群号。通知会发送到对应群聊，可开启「群消息@全体成员」提醒全员。
- **消息类型过滤**：MoviePilot 的消息按类型（如订阅、下载、整理等）分类。「私聊消息类型」与「群聊消息类型」分别控制两类目标的过滤范围。群聊消息类型留空时自动跟随私聊设置。

### 远程命令控制

1. 开启「启用双向交互」。
2. （可选）在「可交互QQ号」限定允许执行命令的 QQ 号，留空允许全部。
3. 在「上报令牌」填写与 NapCat HTTP 客户端配置一致的 Token，并在 NapCat 侧配置 HTTP 客户端，上报地址为 `http://<MoviePilot地址>/api/v1/plugin/NapCatMsg/report`。
4. 私聊机器人发送命令（如「搜索 流浪地球」），MoviePilot 消息链会识别并执行命令，回复直接发送到私聊会话。

### 群聊交互

配置「机器人QQ号」后，群聊命令需要 @ 机器人激活会话：

- 群聊中首次发送命令需 **@ 机器人**，或 **@ 全体成员**（视为 @ 机器人）。
- 激活后，「群聊会话过期秒数」（默认 300 秒）内发送命令无需再次 @。
- 超时后需重新 @ 机器人激活。
- 不配置「机器人QQ号」时保持直通兼容：群聊命令无需 @ 即可触发。

群聊发起的命令，回复会**回到原群并 @ 发起者**，不会落入私聊。

### 搜索/下载候选列表

通过 QQ 发起搜索、订阅、下载等交互后，MoviePilot 返回的媒体/种子候选列表会以文本形式回复到发起会话：

- 媒体候选格式：`序号. 标题 (年份) [评分]`
- 种子候选格式：`序号. 标题 [站点] 大小GB 做种:数量`

回复数字即可选择对应候选，完成下载闭环。

## 安全说明

- **上报令牌**：NapCat 将上报 Token 用作 HMAC-SHA1 签名密钥（`x-signature` 头），插件按 OneBot11 标准校验，也兼容 Bearer/裸 Token 请求头与 URL 参数。请确保 NapCat HTTP 客户端配置中的 Token 与插件「上报令牌」完全一致；不使用时两侧均留空。
- **可交互名单**：建议在「可交互QQ号」中只填入你自己的 QQ 号，避免他人向机器人发送命令。
- **AccessToken**：调用 NapCat HTTP 接口的令牌建议设置，防止未授权调用机器人接口。
- 插件只保存配置值，不在日志中输出令牌明文。

## 常见问题排查

| 现象 | 可能原因与处理 |
| --- | --- |
| 测试消息收不到 | 检查「NapCat服务地址」是否可达（NapCat 与 MoviePilot 网络互通）；检查「QQ号/群号」是否填写正确；查看 MoviePilot 日志中是否有「NapCat消息发送失败」记录 |
| 发送失败：HTTP错误码 | NapCat HTTP 服务未开启或 AccessToken 不匹配；确认 NapCat 网络配置中的 Token 与插件「AccessToken」一致 |
| 发送失败：接口返回错误 | 查看日志中 OneBot11 接口返回的 `retcode` 与错误信息，常见为消息内容被风控、目标 QQ 号不存在或机器人被移出群聊 |
| 上报鉴权失败 | 日志提示「NapCat消息上报鉴权失败」：确认 NapCat HTTP 客户端 Token 与插件「上报令牌」完全一致（含大小写）；或将 NapCat 侧 Token 留空并在插件侧清空上报令牌 |
| 群聊命令不响应 | 配置了「机器人QQ号」但未 @ 机器人；或会话已过期，需重新 @ 机器人激活 |
| 消息重复发送 | 检查是否同时安装了其他 QQ 渠道插件（如官方 QQ 机器人模块）造成渠道竞争；本插件对广播与定向路径做了互斥分区，正常不会重复 |
| 无法接收群聊命令回复 | 确认群聊命令消息带有群 ID 上下文；插件会通过活跃群会话补全回复目标，若会话过期会回退私聊 |

## 更新与卸载

- **更新**：在 MoviePilot 插件市场检测到新版本后点击更新即可，配置会保留。
- **卸载**：卸载后插件停止收发消息，不会影响 MoviePilot 其他功能；NapCat 侧的 HTTP 客户端上报地址可一并清理。

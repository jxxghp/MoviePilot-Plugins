# 音乐资源管理

面向 MoviePilot V3 的音乐工作台，明确拆分三个场景：

1. **下载艺术家大合集**：按 MusicBrainz 艺术家身份搜索 PT 大合集，一次只允许选择一个资源；解析种子内部文件清单后展示“确认覆盖 / 可能覆盖 / 未覆盖”的 Album、EP、Single。
2. **补全缺失作品**：以 MusicBrainz 官方作品目录对比媒体库，只列出明确缺失的作品；媒体库查询失败时标为未知，不会自动当成缺失；精确匹配资源默认选中。
3. **资源命名预览**：列出音乐下载任务，手工填写标准名称后预览目标路径。留空归档根目录时保持当前保存位置；填写根目录时预览 `主类别 / 艺人 / 作品（年份）`。本版本严格只读，不执行改名/移动，也不宣称已完成 MusicBrainz 自动识别。

最低宿主版本：MoviePilot 3.1.2。配置中启用后，从“媒体整理 → 音乐资源管理”侧栏入口，或插件详情页打开。插件不需要修改主程序或前端。

## 当前范围

- MusicBrainz 的 Album、EP、Single 作品目录；目前排除 Compilation、Live、Remix、Soundtrack、DJ-mix、Mixtape/Street 次类别。MusicBrainz 的未收录条目无法由本插件推断补出。
- 合集最多解析 32 个候选，按清单命中、可能覆盖和做种数排序，展示最多 12 个。搜索失败或未命中不等于站点绝对没有资源。
- “清单命中”只表示子目录/音频文件名与作品有身份线索，不等于曲目、版本或音质完整。合集年份范围永远只算“可能覆盖”。同名不同类型/年份证据不足时不会确认。
- 已存在表示音乐库中发现相同作品，不代表曲目完整；已存在项不参与缺失补全。音乐库数量与枚举结果不符、未配置音乐库或提供方异常时，未命中条目标为未知。
- 下载记录表示宿主接受了提交，不表示下载完成、整理完成或刮削完成。后续整理与刮削沿用宿主已有配置及能力；本插件不修复既有错误历史。

## 安全边界

- PT 站 Cookie、UA、代理设置和下载票据只保留在后端短时内存，不发送到浏览器，也不写入插件数据。
- 合集探测只下载种子元数据，不会向下载器提交任务。
- 下载艺术家大合集时一次只提交一个合集，不再和逐作品补全混在同一按钮里。
- 做种中的文件不通过文件系统直接改名；即使宿主存在 `rename_torrent_content` 方法，也不会自动解锁写入。API 层拒绝所有 `execute=true` 请求。
- 下载候选绑定后端确认的艺术家、模式和作品，短时有效且一次性消费。浏览器不能替换作品元数据；只允许精确作品候选下载。补全提交前再次核对媒体库，避免旧页面重复下载已存在作品。
- 所有 API 都要求激活账号及管理权限。停用插件清空候选并阻止下载。额外请求不会绕过 UI 限制。

## 配置

- `下载资源根目录`：可选。留空时跟随 MoviePilot 的下载目录设置。
- `按 Artist Collection/艺人 分类`：设置资源根目录后，大合集下载目录为 `资源根目录/Artist Collection/艺人`。

## 后续小型核心 PR 的边界

单独新增一个 `rename_torrent_content` 原语并不足以安全解锁本插件。下一阶段先与主程序维护者确认通用能力合同：

```python
rename_torrent_content(hash_string, downloader, old_name, new_name, kind)
```

1. 核心只负责通用下载器根目录/单文件重命名、任务快照及最终路径/文件清单校验；返回“接受请求”不能等同“已同步”。
2. 源文件变更后经宿主公开服务同步下载历史/转移任务路径；不能由插件直接改宿主数据库模型。
3. 插件负责 MusicBrainz 识别、命名规则、类别与交互，不往下载/整理主流程塞音乐专项规则。
4. 规范化计划持久化、并发锁、失败后的继续校验/恢复，以及三处入口统一，再单独开发并验收。
5. 合集整理历史分层、整包重新整理刮削、艺人头像补全属于后续阶段，不能把本版视为此前实验功能的完整替代。

本插件 PR 与这些宿主能力无强制依赖；初版不变更任何 qB 源文件。

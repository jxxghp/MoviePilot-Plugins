# 动态企微可信IP

按周期取 MoviePilot 出口网络的公网 IPv4，写进企业微信自建应用的「可信IP」白名单；
登录态失效时提醒管理员重新扫码，不需要每天去后台手工改。全程只发普通 HTTP 请求，
不启动任何浏览器内核。

要求 **MoviePilot v3.2.9 及以上**（登录二维码使用宿主统一的原始图片协议）。
本实现只提供 V3，`plugins.v2` 里的是 1.x 历史版本，不再维护。

## 它解决什么

自建应用的可信IP白名单会拒绝未登记地址的服务端调用。家宽、线路或容器出口换 IP 之后，
接口就从可用变成报 `60020 不安全的访问IP`，而后台修改要人工盯着。插件把这件事变成自动的：
先比对各应用当前的白名单是否已包含本轮 IP，缺少才提交。

写入时只提交当前这一个 IP，不会把后台已有的其它条目读出来再回提。如果你在同一应用上
还手工维护别的可信地址，请先确认企业微信后台对这种提交的保留策略，再决定是否共用该应用。

## 资源占用

没有浏览器：不加载 Playwright / Selenium，不拉起 Chromium 之类内核，不产生无头进程与页面缓存。
只依赖宿主自带的 `requests`，插件目录下没有额外依赖文件，安装不需要再装东西。

常态开销是一路 cron 调度加一个复用的 HTTP 会话。默认 10 分钟一轮，下表数的只是
**HTTP 请求次数**：公网 IP 每轮只查一次、通知每轮只发一条汇总、详情页记录每轮归并成一组。

| 动作 | 每轮 HTTP 请求数 | 超时 |
| --- | --- | --- |
| 判定登录态（拉一次企业信息） | 1 | 10 秒 |
| 查询当前公网 IPv4 | 1（命中即停，失败才换下一个候选） | 3 秒 |
| 读取各应用可信IP列表 | 应用数（企业微信按 `app_id` 逐个读） | 10 秒 |
| 写入可信IP | 缺少当前 IP 的应用数（同样按 `app_id` 逐个提交） | 15 秒 |

读和写都是按 `app_id` 提交的，所以计次跟着应用数走；一轮之内公网 IP 只查一次，多个应用共用同一个值。
白名单已包含当前 IP 时，本轮只有读取类请求（判定登录态、查 IP、逐个应用读列表），不写入也不发通知。

内存里只留少量状态：最近一张二维码图片用于投递（不落盘、不进缓存目录）、本次登录的图片
访问令牌（180 秒过期），运行数据只保留最近 5 条写入结果与一个失败计数。扫码期间的等待放在
单独的工作线程里，不阻塞宿主事件线程，登录完成或超时即退出。关闭插件会取消定时器并关掉会话。

日志同样不放大：取 IP 的网络波动只记一条，多应用逐个校验的明细降为 debug，
同一轮检测的多次写入在详情页归并成一组。

## 实现方式：只调后台 HTTP 接口

插件用 `requests` 直接请求企业微信管理后台的接口，请求头伪装成后台页面里的 AJAX
（浏览器 UA、`sec-ch-ua`、`x-requested-with: XMLHttpRequest`、`referer`），所以流量看起来
「像浏览器」，实际没有任何浏览器内核参与（开销见上一节）。

可信IP 属于管理后台的应用配置项。本插件没有走 CorpID / CorpSecret 换 `access_token` 的
开放接口路线，所以配置页只有「应用ID」和「检测周期」两项必填，没有 Secret 输入框；
代之以一次管理员扫码换取会话 Cookie（`wwrtx.sid`），登录后由插件写进自己的配置。

实际调用的接口都在 `https://work.weixin.qq.com/wework_admin/` 下：

- `wwqrlogin/mng/get_key` 取本次登录的 `qrcode_key`；`wwqrlogin/mng/qrcode` 取二维码图片；
  `wwqrlogin/mng/check` 轮询手机确认（30 秒内未确认即本次失效）。
- `loginpage_wx` 用扫码回传的 code 完成登录，`redirect_uri` 只是指向后台首页 `frame`。
- `mobile_confirm/confirm_captcha` 提交 6 位短信验证码；多企业账号随后走 `login/choose_corp` 选企业。
- `contacts/party/cache` 拉一次企业信息用来判定登录态，每轮检测的第一步就是它。
- `apps/getCorpAppV2` 读应用当前的可信IP列表；`apps/saveIpConfig` 写入可信IP。

代价要一并说清楚：这些是后台页面在用的接口，企业微信改版时可能失效，表现为读取或写入报错，
届时需要更新插件；Cookie 也会过期，插件会按下面「登录失效与提醒节奏」的规则提醒重新扫码，
不会静默不管。

## 第一次使用

1. 打开「启用插件」，填写**应用ID**（多个用英文逗号分隔）。应用ID 在企业微信管理后台
   应用页面 URL 末尾的 `app_id=` 参数。
2. **检测周期**保持默认 `*/10 * * * *`，或按需要改成自己的 5 位 cron。
3. 保存后发送 `/update_wechat_ip`，用**有管理权限的企业微信账号**扫描收到的二维码。
4. 扫码后按提示输入 6 位短信验证码：数字按钮、回复 `/update_wechat_ip 验证码`、
   或先按「直接输入」再发验证码都可以。
5. 登录成功后 Cookie 自动写入插件配置，之后每轮检测自动维持白名单，无需再管。

「立即检测一次」只在本轮生效：保存后约 3 秒执行一次检测，开关随后自动复位。

## 配置说明

| 配置项 | 必填 | 说明 |
| --- | --- | --- |
| 启用插件 | - | 关闭后停止调度与清理后台会话，未登录提醒也随之停止 |
| 检测周期 | 是 | 5 位 cron，默认 `*/10 * * * *`；每轮先查登录态，再查 IP |
| 应用ID | 是 | 逗号分隔，按填写顺序处理并自动去重；留空则跳过白名单校验 |
| IPv4 查询接口 | 否 | 逗号分隔，按顺序尝试；留空或全部无效时使用内置列表 |
| 立即检测一次 | 否 | 保存后单次执行，不影响 cron 周期 |

内置 IPv4 查询地址：`myip.ipip.net`、`ddns.oray.com/checkip`、`ip.3322.net`、
`ipv4.ddnspod.com`、`ipv4.ip.mir6.com`。全部失效时会记一条警告并退回内置列表。

登录 Cookie（`wwrtx.sid`）不在配置页显示，由扫码流程写入与更新，请勿手工编辑配置文件里的该字段。

## 每轮检测做什么

1. 处于登录失效降频期则直接跳过本轮。
2. 校验登录态：未登录记一次失败，达到阈值后按下面的节奏提醒。
3. 取当前公网 IPv4；取不到就跳过本轮，不会把空值写进白名单。
4. 逐个应用读取白名单，比对是否已包含本轮 IP。
5. 只向缺少该 IP 的应用逐个调用写入接口，结果汇总成**一条**通知，按成功、部分失败、
   全部失败三种措辞给出，失败时列出应用ID；全部已包含时不产生任何通知，只留一条 debug 日志。

记录最多保留最近 5 条写入结果（按应用计），详情页按「状态 / 应用ID / 更新IP / 结果 / 更新时间」
展示；同一次检测写入的多个应用共用一个时间戳，归并成一组显示，不会按秒拆行。

## 登录失效与提醒节奏

连续 3 次检测到登录失效后进入降频：每 30 分钟才重试并提醒一次，登录恢复后计数清零。
提醒投递规则：

- 首次失效不指定渠道，交给宿主按已配置的通知渠道分发，站内消息与聚合类通知插件都能收到。
- 之后的重复提醒逐个发给已启用的通知渠道，站内（`Web` / `WebAgent`）只在首次出现，
  避免消息中心堆积同一条失效提示。
- 提醒文案固定为「企业微信登录状态失效，请发送 /update_wechat_ip 获取二维码重新登录」。

## 二维码在不同渠道的显示

- 站内页面（`Web` / `WebAgent`）直接渲染图片，使用同源相对地址，不需要额外配置。
- 其它渠道由宿主统一上传原始图片；渠道不支持图片投递时，如果配置了可对外访问的地址，
  消息里会附带图片链接；两者都没有则提示「请在 MoviePilot 页面打开本插件获取二维码」。
- 二维码图片地址形如 `GET /api/v1/plugin/UpdateWeChatIp/img/{编号}?t={令牌}`。令牌在本次
  登录签发、180 秒有效，重新获取二维码会让旧令牌立即失效；上一张待扫的二维码同时作废，
  消息里会写明「上一次待扫码的二维码已失效，请以本次为准」。

## 命令与按钮

| 用法 | 作用 |
| --- | --- |
| `/update_wechat_ip` | 获取登录二维码 |
| `/update_wechat_ip 扫码完成` | 按钮不可用时，声明已扫码并进入验证码环节 |
| `/update_wechat_ip 123456` | 直接提交 6 位短信验证码 |
| 数字按钮 + 退格 / 清空 / 直接输入 / 输入完毕 | 在聊天里逐位输入验证码 |

文本输入会话 120 秒超时；宿主未提供文本输入会话接口时，插件会提示改用数字按钮或命令。

## 对外接口

需要立刻修正白名单（例如 DDNS 换 IP 的脚本里）可以直接调用插件 API，认证方式与主程序 API 相同：

```
POST /api/v1/plugin/UpdateWeChatIp/UpdateIP?ip=1.2.3.4
```

只接受合法 IPv4，否则返回 400。响应给出写入应用数量与 `failed_app_ids`，
写入结果同时进入详情页的更新记录。

## 常见错误对照

| 企业微信返回 | 含义与处理 |
| --- | --- |
| `-3` / `-4` / `outsession` | 登录已失效，重新扫码 |
| `60020` / `invalid ip` | 当前出口 IP 未被信任，正是本插件要解决的问题；若反复出现说明 Cookie 已失效或写入未生效 |
| `-80037` | 应用ID 不存在，检查填写的 `app_id` |
| `-30001` | 参数错误，多为应用ID 格式异常 |
| `-1` / `-80013` | 企业微信侧繁忙或异常，等下一轮重试 |
| `HTML页面(N 字符)` | 被重定向到登录页，等同于登录失效 |

## 常见问题

- **换了 IP 却没更新**：先确认已登录——未登录时不会写入；再看应用ID 是否填写、
  日志里是否有「未配置应用ID」或「获取当前公网IP失败」。
- **取到的 IP 不是预期出口**：查询接口反映的是容器实际对外连接的地址。多网卡、
  独立出口的容器或代理链路下结果可能不同，可自定义 IPv4 查询接口指向能返回目标地址的服务。
- **多个应用漏了更新**：应用ID 必须全部填在同一个配置项里；写入失败的应用会出现在通知
  与接口的 `failed_app_ids` 中，不会报「成功」。
- **能否指定只更新部分应用**：可以，把「应用ID」只填需要维护的那几个；其余应用不受影响。
- **插件会不会改动其它后台设置**：只调用 `saveIpConfig` 提交可信IP，不改动应用的其它配置项。

## 权限与数据

市场索引把本插件的可见级别设为超级管理员，配置页、详情页与命令对普通用户不可见。
Cookie 与更新记录保存在本插件自身的配置和运行数据中；二维码图片只在内存中保留最新一张
用于投递，不落盘、不进入缓存目录，也不留下任何浏览器或页面缓存残留。

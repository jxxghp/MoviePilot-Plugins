# 站点自动签到

可分别选择需要签到和模拟登录的站点；“全部”会在每次运行时包含当前所有站点。

本版本要求 **MoviePilot v3.1.6 及以上**，插件市场通过 `system_version: >=3.1.6` 显式限制主程序版本。

开启“发送通知”后，“优化消息通知样式”默认开启；关闭该开关即可恢复原有完整纯文本样式。
富文本支持 Telegram Rich Message、飞书 Markdown 卡片、Slack Block Kit，以及
钉钉、Discord、VoceChat、Synology Chat、企业微信智能机器人和具备 Markdown 权限的 QQ Bot。
企业微信应用模式与其他不支持的渠道保留原有纯文本；QQ Markdown 权限不足时自动回退。
通知先显示日期和本次统计，再按失败、仅登录、确认成功分组；下次执行的站点会显示 `↻` 标记，
重试标记不代表签到失败。展示全部站点，超过渠道单条消息限制时自动分段发送。
长名称和结果会缩短，完整结果保留在插件详情。
其他渠道和通知中心继续使用原有完整纯文本通知；关闭样式开关后，所有渠道均恢复旧样式。

执行结果分为三类，通知会分别计数：

* **签到成功**：站点返回明确的完成状态、签到奖励或接口业务成功结果。
* **登录成功，签到未确认**：已确认登录访问，可用于登录保号；没有把握已完成签到，不能计入签到成功。
* **登录或访问失败**：未确认登录，保留网络、验证码、登录失效等实际原因。

签到接口返回 404、没有登录导航或签到结果未知时，会使用相同站点配置访问首页或专用登录接口确认登录。
签到页面已经有登录凭据时不重复访问首页。仅提供模拟登录功能的站点会明确标记“未执行签到”。
HTTP 200、签到按钮消失、跳回签到页、脚本或隐藏模板中的文案都不能单独证明签到或登录成功。

馒头的签到和模拟登录共用更新访问时间接口，每轮任务只请求一次；失败结果直接保留。
普通站点回退验证登录时，相同错误只显示一次，不同失败原因会合并展示。

未确认登录的失败结果会在下一次任务运行时重试，不受自定义重试关键词限制。
已登录但签到未确认视为完成本轮访问，默认的“错误|失败”关键词不会再次选中它。
重试关键词仍可额外选中其他结果；未填写关键词时保留每次重新执行全部已选站点的行为。

详情页分别显示签到状态与登录状态：只确认登录的站点，签到显示未确认，登录显示成功。
历史保存实际返回结果和登录证据，不把“执行过”显示为“已签到”；历史保留含当天的最近 14 天。
旧版未保存验证结果的成功记录标记为历史结果未确认，当天缺少明确结果的旧记录会重新执行验证。

签到 API 的 `success` 仍只表示确认签到；`data.signin_success` 和 `data.login_success` 分别提供签到和登录状态。

海胆之家（haidan.cc）使用专用打卡接口，按站点配置地址先访问 `signin.php`，再携带 Cookie 读取 `index.php`，仅在页面出现“已经打卡”按钮时确认签到成功。

学校（btschool）签到成功只在一次性到账提示“今天签到您获得X点魔力值”中出现，插件在签到响应上读取该提示确认结果。

馒头（m-team）没有独立签到接口，通过前端 `updateLastBrowse` 接口生成签名并更新访问时间保号：需要在站点配置的请求头（Authorization/Token）中填写浏览器登录态，登录态过期后需重新登录站点更新。

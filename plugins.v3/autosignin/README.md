# 站点自动签到

可分别选择需要签到和模拟登录的站点；“全部”会在每次运行时包含当前所有站点。

本版本要求 **MoviePilot v3.2.6 及以上**，使用主程序提供的站点连接检测能力。

开启“发送通知”后，“优化消息通知样式”默认开启；关闭该开关即可恢复原有完整纯文本样式。
富文本支持 Telegram Rich Message、飞书 Markdown 卡片、Slack Block Kit，以及
钉钉、Discord、VoceChat、Synology Chat、企业微信智能机器人和具备 Markdown 权限的 QQ Bot。
企业微信应用模式与其他不支持的渠道保留原有纯文本；QQ Markdown 权限不足时自动回退。
通知先显示日期和本次统计，再按失败、仅登录、确认成功分组；下次执行的站点会显示 `↻` 标记，
重试标记不代表签到失败。展示全部站点，超过渠道单条消息限制时自动分段发送。
失败组按错误语义归类，成功和仅登录组按相同结果原因归并；类别或原因只显示一次，下面列出全部对应站点。
失败摘要去掉重复的动作前缀，合并同义错误及不同入口附带的原因；原始错误完整保留在插件详情和纯文本通知中。
Telegram 的分组标题、原因与站点名单使用主程序的 Rich Message 分节及缩进列表渲染。
长名称和结果会缩短，完整结果保留在插件详情。
其他渠道和通知中心继续使用原有完整纯文本通知；关闭样式开关后，所有渠道均恢复旧样式。

执行结果分为三类，通知会分别计数：

* **签到成功**：站点返回明确的完成状态、签到奖励或接口业务成功结果。
* **登录成功，签到未确认**：已确认登录访问，可用于登录保号；没有把握已完成签到，不能计入签到成功。
* **登录或访问失败**：未确认登录，保留网络、验证码、登录失效等实际原因。

失败通知的分类规则：

* **Cookie / Token / 登录状态异常**：凭据失效、需要登录和未识别到登录状态归入同组；附带的签到入口 404 不再拆成新组。该标题不代表所有站点的 Cookie 都已确认失效。
* **站点配置缺失**：站点信息、地址或 Cookie / Token / API Key 未配置，不能与已配置但失效的凭据混为一类。
* **Cloudflare 防护验证失败**、**验证码获取或校验失败**、**网络请求超时**、**网络连接失败**独立分类，同义错误合并展示。
* HTTP 403、429 和 5xx 分别归为访问被拒绝、访问频率受限和站点服务异常；其他 HTTP 错误保留状态码，不把单独的 404 归为 Cookie 问题。
* 页面或接口解析异常、结果未确认分别归类；未知业务错误仍按原始原因分组，不强行合并。

明确的配置缺失或凭据失效优先于伴随错误；只有“未识别到登录状态”时，不覆盖实际防护、验证码、网络、非 404 HTTP 或页面异常。
分类仅影响优化通知摘要，不改写执行结果、历史、Cookie 自动更新事件或重试关键词依据。

签到接口返回 404、没有登录导航或签到结果未知时，会使用相同站点配置访问首页或专用登录接口确认登录。
签到页面已经有登录凭据时不重复访问首页。仅提供模拟登录功能的站点会明确标记“未执行签到”。
HTTP 200、签到按钮消失、跳回签到页、脚本或隐藏模板中的文案都不能单独证明签到或登录成功。

高清杜比、猪猪通过主程序 API 适配器提供的站点连接检测验证登录。
API 地址、API Key / Token、UA、代理和超时沿用 MoviePilot 站点配置，猪猪兼容 Token 中的长期存取令牌。
验证通过显示“登录成功，签到未确认”，计入仅登录。本轮 API 检测失败时直接保留实际原因，留待下一次任务重试。
普通网页站点继续使用 Cookie，已有专用签到接口的站点使用对应的签到处理器。

馒头的签到和模拟登录共用更新访问时间接口，每轮任务只请求一次；失败结果直接保留。
普通站点回退验证登录时，原始结果中的相同错误只保留一次，不同失败原因合并保留在详情中。
同时选择签到和登录的站点，登录任务复用本轮签到及回退验证的结果，保存登录历史，避免重复请求与结果通知。
单独选择登录的站点仍正常执行并发送登录通知；签到未确认而已确认登录的站点仍不计入签到成功。

未确认登录的失败结果会在下一次任务运行时重试，不受自定义重试关键词限制。
已登录但签到未确认视为完成本轮访问，默认的“错误|失败”关键词不会再次选中它。
重试关键词仍可额外选中其他结果；未填写关键词时保留每次重新执行全部已选站点的行为。

详情页分别显示签到状态与登录状态：只确认登录的站点，签到显示未确认，登录显示成功。
两张状态表使用一致的列宽，“今日”标题与状态统一左对齐。
历史保存实际返回结果和登录证据，不把“执行过”显示为“已签到”；历史保留含当天的最近 14 天。
旧版未保存验证结果的成功记录标记为历史结果未确认，当天缺少明确结果的旧记录会重新执行验证。

签到 API 的 `success` 仍只表示确认签到；`data.signin_success` 和 `data.login_success` 分别提供签到和登录状态。

海胆之家（haidan.cc）使用专用打卡接口，按站点配置地址先访问 `signin.php`，再携带 Cookie 读取 `index.php`，仅在页面出现“已经打卡”按钮时确认签到成功。

学校（btschool）签到成功只在一次性到账提示“今天签到您获得X点魔力值”中出现，插件在签到响应上读取该提示确认结果。

PTZONE（ptzone.xyz）按配置地址向 `attendance.php` 提交 POST 签到，保留 Cookie、UA、代理和超时配置；仅在返回页面同时确认登录和签到完成时记为成功。

AGSVPT（agsvpt.com）使用专用签到处理器，先读取 `attendance.php`，出现“立即签到”按钮时提交 POST，并通过签到成功或奖励文案确认结果。

馒头（m-team）没有独立签到接口，通过前端 `updateLastBrowse` 接口生成签名并更新访问时间保号：需要在站点配置的请求头（Authorization/Token）中填写浏览器登录态，登录态过期后需重新登录站点更新。

高清视界（hdarea.club）从 `3.0.8` 起支持官方 API：在 MoviePilot 站点 **API Key** 中填写站点存取令牌，
并勾选令牌的 `user` 权限以执行 `POST /api/v1/user/signin`。模拟登录使用 `GET /api/v1/user/profile`，需要 `read` 权限。
API Key 已配置时，签到及失败后的登录确认都不使用 Cookie；API 失败不会重试网页签到或被当成签到成功。
未配置 API Key 的存量站点仍使用原有 `sign_in.php` Cookie 签到。

# 影视简介增强（MediaOverviewEnhancer）

MoviePilot V3 插件：把电影简介写得更详细、让剧集每集都有独立简介，并支持为 MV（音乐视频）
生成中文简介；结果写回 Emby 并锁定字段，避免被后续刮削覆盖。

## 功能

- **电影简介扩写**：TMDB 中文简介优先；素材不足时按配置翻译英文简介，或由 AI 依上下文扩写到目标字数。
- **剧集分集独立简介**：每集用自身的剧集信息（分集标题 / 播出日期 / TMDB 分集简介）单独生成，
  不再整季共用同一段简介；可跳过特别篇。
- **MV 简介**（v1.2.0 起）：MV 没有 TMDB / IMDb 条目，改为从文件名解析出
  艺人 / 曲名 / 年份 / 版本标注作为素材，由 AI 生成中文简介；提示词带硬约束，
  并会把混进文案的画质、编码等技术描述整句剔除。
- **三种触达方式**：整理入库后自动补全（可设延迟）、插件详情页手动试跑 / 批量执行、定时补漏扫描。
- **通知推送**（v1.3.0 起）：任务结束可通知成功 / 跳过 / 失败统计；有失败条目时单独提醒；
  可开启每日固定时间（如 21:00）汇总当天成功处理条数。
- **MV 演员信息**（v1.4.0 起）：MV 在 Emby 里是视频条目、没有 TMDB 演职员数据，
  插件会把文件名解析出的艺人写入条目的「演员」（People）区域，角色名可自定义（默认「演唱」），
  并把 Emby 的 `Cast` 字段一并锁定，避免后续刮削覆盖；已有演员条目会被保留，不会重复追加。
  简介已达标、只是缺演员的 MV 也会被补上演员，不需要重写简介。
- **NFO 元数据文件**（v1.7.0 起）：MV 的简介与演员可同时写入**与视频同名的 `.nfo`**，
  供 Kodi / Jellyfin / Emby / Infuse 等读取 NFO 的客户端使用；只新增文本文件，
  不改动视频本体（不影响硬链接与做种）。路径映射默认 `/media/:/medias/media/`，可在配置里改。
- **演员头像**（v1.8.0 起）：自动为演员查询头像（**TMDB → Wikidata → Wikipedia**），
  写进 Emby 的人物头像，并作为 `<actor><thumb>` 写入 NFO（可指向本地已下载的图片）；
  查询结果持久缓存，不会重复请求外部接口。
- **合作艺人拆分**（v1.9.1 起）：`A & B`、`A feat. B`、`A、B` 这类合作署名会拆成单个艺人，
  各自署名并分别取头像（整串组合名不是自然人，查不到人物图）；本身含分隔符的艺名
  （如 `AC/DC`、`Earth, Wind & Fire`）保持原样、不拆。
- **补漏自检**（v1.9.0 起）：NFO 缺失 / 简介不一致 / 缺演员 / 缺头像，以及 Emby 里
  已写入但缺人物头像的演员，都会被识别为待处理；新增「仅补 NFO/头像」模式，
  只修复派生产物、不改写简介。
- **失败可追踪可重试**（v1.9.0 起）：大模型调用失败不再被算作「跳过」，
  而是进入失败清单（含原因与次数），可按配置做指数退避重试，并支持一键重试全部失败项。
- **旧简介备份与回滚**（v1.9.0 起）：写入前保存旧简介与锁定状态（默认保留 30 天），
  详情页可单条回滚或回滚最近一轮，AI 文案跑偏时能恢复。
- **质量闸门**（v1.9.0 起）：中文占比过低（疑似未翻译）、仍在描述画质/编码、
  过于模板化的简介会被判为失败，不会写入媒体库。
- **电影标题兜底**（v1.9.0 起）：电影缺少 TMDB 标识时，也可按「标题 + 年份」严格匹配
  TMDB（此前该开关只对剧集生效）。
- **试跑增强**（v1.9.0 起）：可生成 1–5 条样张文案（不写入）、按来源筛选、
  对单条执行强制重做。
- **成员数据源与名字模式**（v1.6.0 起）：成员数据源可选 **MusicBrainz / Wikidata / 两者并集**
  （Wikidata 自带中文成员名，MusicBrainz 覆盖更广）；成员名显示方式可选
  **中文译名 / 原始名称 / 中文+原名**（如「李彩琳 (CL)」）。
- **MV 团队成员**（v1.5.0 起）：团体成员名单取自 **MusicBrainz**，可与团体名一起写入演员；
  成员角色名默认「成员」；查询结果会持久缓存，避免重复请求外部接口。
- **安全写入**：写入时整份条目回写并自动回读校验（不会清空名称 / 分集号）；
  简介写入后并入 `LockedFields`，Emby 后续刮削不会覆盖。
- **可见进度**：详情页可看待处理清单、成功 / 跳过 / 失败统计与处理记录，可一键清空记录。

## 工作原理

1. 通过 MoviePilot 的媒体服务器服务连接 Emby，按你选定的服务器与媒体库读取条目。
2. 按条目标识（TMDB / IMDb）取元数据，生成优先级为：**TMDB 中文简介 → 英文翻译 → AI 生成**
   （各类型可在配置里调整模式）。
3. 写入使用完整 DTO 回写：补齐 `ProviderIds`、剔除 `UserData`、把 `Overview` 并入 `LockedFields`，
   写完自动回读校验。
4. 重复检测：已有简介达到字数的条目默认跳过，勾选「强制重写」才会重做；
   同季分集简介雷同时（素材不足）可自动改用 AI 生成。
5. **成本保护**：处理对象选「全部」时**不包含 MV**，避免一次性产生大量大模型调用；
   要处理 MV 必须显式选「仅 MV」。

## 使用

1. 「设置」页启用插件，勾选要处理的媒体服务器（留空表示全部已配置 Emby）；
2. 打开插件详情页，把「处理对象」选为 `全部 / 仅电影 / 仅剧集 / 仅 MV`，
   先点「**试跑（不写入）**」核对将要处理的条目清单，必要时点「**生成 2 条样张**」确认文案质量；
3. 确认后点「**立即执行**」，运行中可随时「停止」，结束后在页面查看统计；
   MV 的 NFO / 头像补漏选「**仅补 NFO/头像**」，不会改写简介；
4. 需要长期补漏可在设置里填「定时补漏（小时）」，也可以用「入库后自动补全」在整理完成时触发
   （可设延迟秒数，等 Emby 刮削完成后再写）。

## 配置项

| 分组 | 配置 | 说明 |
| --- | --- | --- |
| 通用 | 启用插件 | 总开关 |
| 通用 | 媒体服务器 / 媒体库 | 处理范围，留空表示全部 |
| 通用 | 入库后自动补全 / 延迟（秒） | 整理完成事件触发，延迟等待 Emby 刮削 |
| 通用 | 定时补漏（小时） | 0 表示关闭；大于 0 时按间隔扫描补漏 |
| 通用 | 增量扫描天数 | 0 表示全库；大于 0 时只处理最近 N 天入库的电影/剧集 |
| 电影 | 开关 / 模式 / 最小字数 / 目标字数 | 模式：扩写（TMDB 中文→翻译→AI）/ 仅翻译 / 仅 AI |
| 剧集 | 开关 / 模式 / 最小字数 / 目标字数 | 模式：自动（TMDB 分集简介优先）/ 仅 TMDB / 仅 AI |
| 剧集 | 始终重写 / 跳过特别篇 | 分集简介是否无条件重写、是否跳过 SP |
| MV | 开关 / 媒体库 / 字数 / 写入演员 / 角色名 / 合作艺人拆分 / 团队成员 / 成员角色 / 成员名模式 / 成员数据源 / NFO / 自检 | 默认库名 `mv`，只在「仅 MV」时生效；演员写入 Emby `People`（锁定 `Cast`），可选写同名 `.nfo`；合作艺人拆分会把 `A & B` 拆成单个艺人分别取头像；自检会补缺失的 NFO 与头像 |
| MV | NFO 根元素 / 路径映射 | `movie` 兼容 Emby/Kodi 视频库，`musicvideo` 供 Kodi 音乐视频库；映射支持分号分隔多组 |
| 数据源 | 翻译外文简介 / 缺失时 AI 生成 / 素材不足时改用 AI / 无 TMDB 标识时按标题搜索（电影 + 剧集） | 决定兜底链路 |
| 质量 | 质量闸门 / 中文占比下限 / 大模型重试次数 / 备份保留天数 / 备份条数上限 | 拦截未翻译或空泛文案，失败可重试，旧简介可回滚 |
| 写入 | 重复检测 / 锁定简介 / 强制重写 | 锁定会写入 Emby 的 `LockedFields` |
| 运行 | 并发数 / 单次上限 / 侧栏入口 | 并发默认 2，单次默认最多 200 条 |
| 通知 | 任务完成通知 / 失败提醒 / 每日汇总 + 时间 | 通知走 MP 已配置消息渠道；每日汇总统计当天 0 点起的结果 |

## 前置条件

- MoviePilot **V3（≥ 3.0.0）**
- 已配置 **Emby** 媒体服务器（写回目标；请确认该服务器下媒体库路径可被 MoviePilot 读取）
- 使用「翻译」或「AI 生成」时需要 MoviePilot 的 **LLM 配置可用**

## 安装

在 MoviePilot 的「设置 → 插件市场地址」中加入本仓库地址：

```
https://github.com/jxxghp/MoviePilot-Plugins
```

随后在「插件」页面刷新市场，搜索「影视简介增强」即可安装。

## 注意

- 插件会**修改 Emby 中的简介字段**（并锁定）。建议第一次先在少量媒体上用「试跑」确认效果，
  再决定是否批量执行。
- AI 生成的内容基于元数据与文件名线索，模型看不到画面，因此 MV 简介多为
  「曲目 + 发行 + 风格」层面的描述。
- 批量处理会消耗大模型调用额度：请留意「并发数」「单次上限」与「仅 MV」的显式选择。

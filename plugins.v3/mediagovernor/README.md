# 媒体治理（MediaGovernor）

MoviePilot V3 的最后一道整理兜底。MoviePilot 仍是唯一执行整理、删除旧硬链接和重建新硬链接的主体；本插件把下载包拆成作品单元，先交叉核验原生候选与整包标题、年份、类型，冲突时才使用批量 AI 并回查 MoviePilot 数据源详情，再以官方逐文件预览和当前目标的差异判定问题。

## 检查什么

检查从当前下载区与当前媒体库开始；成功/失败历史只用于关联来源与既有目标，绝不再把历史条数当成问题数。页面只把有证据的真失败、目录分类/层级/集号/身份错误交给用户；历史目标消失但无法区分手工删除时进入“无法确认”，目录没读完整时进入“未覆盖”，两者都不能说成真实问题。

模型只接收不含路径的名称、层级和数量证据，只能提出身份候选或弃权；不会拥有文件写入权限。最终的“应有结果”仍以 MoviePilot 官方逐文件预览为准。

首次建立地图会读取完整下载证据。从 4.4 升级后的第一次检查也会重读一次文件结构来淘汰旧版错误结论，但复用文件未变作品的原生身份；完成后默认只比较第一层文件指纹和已记录的目标目录，未变化作品不再深扫或重复识别。单个只读请求有明确等待上限，某个样本失败不会丢掉同作品的其他成功样本；智能助手使用小批量并在首次超时后停止后续批次。页面始终显示当前真实阶段、阶段完成数和耗时。“完整重建地图”仅用于地图损坏、目录合同变化或明确重新基线。

## 整理正确

确认作品后，页面按作品类型选择唯一媒体库，再调用 MoviePilot 的 `transfer/manual` 预览。预览完整才可由用户二次确认执行；最终仍由 MoviePilot 清理命中成功历史的旧媒体库硬链接，再从下载原文件重建。插件不调用 `storage/delete`，不会删除下载原文件。

## 边界

- 检查、候选和预览均为零写入；
- 模型只接收不含路径的名称、层级和数量证据；
- 事件监听只记录脱敏历史 ID、状态和标题线索，不读文件、不调用模型；
- 本地构建与合同测试不能替代真实 MoviePilot 加载、预览和用户安装验收。

## 开发验收

`pnpm test:golden` 会运行 47 个完全脱敏的端到端金标准场景，并在仓库的 `runtime/` 生成可打开的验收回执。其中 19 项逐一对应人工核准的当前真失败、假成功、正常样本和 Sample 误报；其余场景覆盖作品拆分、原生与 AI 交叉确认、官方预览和安全执行门。

这套回执是候选门禁，不是 NAS 验收：候选仍需通过真实 V3 的加载、启停和页面注册检查。任何新发现的真实问题都必须先脱敏加入金标准，再修改识别或整理逻辑。

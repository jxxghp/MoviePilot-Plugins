# 媒体治理（MediaGovernor）

MediaGovernor 是 MoviePilot 原生整理之后的兜底：检查当前下载原文件与媒体库硬链接，找出“没有整理成功”和“表面成功但作品、分类、季集或层级错误”两类问题。

## v5 流程

1. 后端只读取 MoviePilot 当前配置中的下载目录、媒体库目录和整理历史；空路径与容器根目录会被拒绝。
2. 下载任务编号是首选作品边界；没有编号时只按明确的独立子目录拆分合集，平铺混包不靠标题猜分组。
3. 原生身份与历史身份一致才自动确认。冲突项由 AI 每批最多四部生成不超过三个搜索词，再回查 MoviePilot 数据源；AI 不能判定文件是否正确。
4. 已确认作品使用 MoviePilot 官方逐文件预览，随后只探测预期目标与历史目标是否真实存在，不遍历整座媒体库。
5. 每部作品单独写入 SQLite 账本；一部失败不会丢掉其他结果，关闭页面也不会中断后台任务。日常检查复用未变化的身份和预览，但重新探测当前目标；高级“重建全部基线”会强制刷新原生身份和官方预览。

结果只分为：已经证明的问题、需要确认、本轮没读完。历史成功目标消失时无法区分主动删除与误删，因此只进入确认区。

## 修复安全门

修复前会再次生成官方预览，并记录原文件、可归因旧目标和新目标的实时指纹。最终确认时再次读取三者并重新运行官方预览；任何变化都会使 token 失效。执行仍由 MoviePilot 官方整理链完成，只有成功历史明确指向且位于当前媒体库中的旧目标才允许清理。执行后必须确认新目标存在、旧目标消失，问题才进入单项复核。插件不会删除原始下载。

## 验收

- `pytest tests/v3/mediagovernor`：v5 后端、真实 V3 导入、任务隔离、AI 批次、修复过期和一次性确认。
- `pnpm test:contracts` 与 `pnpm test:golden`：58 个前端规则合同和 47 个脱敏基线场景。
- 本地合同和构建不是用户体验验收；新发现的真实案例应先脱敏加入固定回放，再修改判断规则。

# 证书管理

手动部署证书、自动申请证书并自动续期，自动重载 nginx。

面向不熟悉证书部署的用户，把「申请 → 部署 → 续期」整条链路收进一个插件，无需手工敲 acme.sh 命令。

## 功能

| 功能 | 说明 |
|---|---|
| 手动部署 | 粘贴证书与私钥 PEM 文本，插件自动校验匹配性、落盘并重载 nginx |
| 自动申请 | 填写域名与 DNS 凭据，插件调用 acme.sh 完成 DNS-01 签发并部署 |
| 自动续期 | 定时调用 acme.sh 检查续期，成功后自动重载 nginx |
| 配置检测 | 逐项校验配置，并真实调用 DNS 服务商接口验证凭据可用性 |
| 状态查看 | 详情页与仪表板展示证书域名、签发机构、有效期与剩余天数（时间为北京时间） |
| DNS 插件下载 | 一键从 acme.sh 官方仓库下载任意服务商的 DNS 插件脚本 |
| 凭据字段查询 | 解析服务商脚本，列出实际需要的凭据字段，覆盖全部 198 个服务商 |
| acme.sh 安装 | 一键从官方仓库下载安装 acme.sh，已安装时执行升级 |

## 快速开始

### 场景一：已有证书，只想部署

1. 打开「设定 → 插件 → 证书管理」
2. 把证书内容粘贴到「证书内容（fullchain.pem）」
3. 把私钥内容粘贴到「私钥内容（privkey.pem）」
4. 点击「部署证书」

插件会校验证书与私钥是否匹配、是否过期，通过后写入 `/config/certs/latest/` 并重载 nginx。校验失败会自动回滚，不会破坏原有证书。

### 场景二：没有证书，想自动申请

1. 填写**证书域名**，如 `example.com`；泛域名写 `*.example.com`；多个用英文逗号分隔
2. 选择或输入 **DNS 服务商**（下拉框可直接输入，见下文「服务商支持范围」）
3. 填写**两个凭据输入框**（见下文「凭据填写说明」）
4. 若服务商不在内置列表，点击「下载 DNS 插件脚本」
5. **点击「检测配置」确认无误**（推荐，见下文「配置检测」）
6. 点击「**申请证书**」，等待 1-3 分钟完成签发与部署

> 所有操作都在**配置页**完成。详情页仅展示当前证书状态。

### 场景三：只想自动续期

1. 开启「启用插件」
2. 确认「acme.sh 目录」与「证书部署目录」正确
3. 保持「续期检查周期」为 `0 4 * * *`（每日 4:00）

## 安全说明

### 凭据存储

DNS 凭据以**明文**保存在 MoviePilot 数据库的 `plugininstance` 表中（与所有 MoviePilot 插件配置的存储方式一致）。因此：

- **数据库文件本身必须视为敏感数据**，不要提交到 Git 或分享
- 建议使用**只有 DNS 解析权限的子账号密钥**，不要用主账号密钥
- 密钥泄露时立即到 DNS 服务商控制台轮换

### 访问控制

| 接口 | 鉴权要求 |
|---|---|
| 插件配置页（含凭据回显） | 超级管理员 |
| `/status`、`/deploy`、`/issue`、`/renew`、`/dnsapi`、`/verify`、`/install`、`/credentials` | 登录用户令牌（`bear`） |

**公网暴露风险**：如果 MoviePilot 直接暴露在公网且未启用 HTTPS，登录令牌可能在传输中被截获，进而被用于调用插件接口。建议：

1. 始终通过 HTTPS 访问（本插件正是为此提供证书管理）
2. 不要在公网环境使用弱密码
3. 必要时通过反向代理限制来源 IP

### 日志脱敏

插件在记录外部命令输出、返回错误详情、读取 acme.sh 日志时，会**自动脱敏**常见凭据字段：

```
Ali_Key=***          Ali_Secret=***
CF_Token=***         DP_Key=***
AccessKeyId=***      HUAWEICLOUD_Password=***
```

覆盖 acme.sh 各 DNS 插件使用的变量名，避免凭据进入日志文件或界面提示。

> 注意：脱敏只针对插件自身产生的日志。如果你在命令行手动执行 acme.sh 并开启 `DEBUG=1`，凭据会出现在终端输出中。

## 配置检测

点击配置页的「检测配置」按钮，插件会**逐项检测**并在任一项失败时立即停止，避免在明显错误的情况下仍然发起外部请求。

### 检测项

| 顺序 | 检测项 | 说明 |
|---|---|---|
| 1 | 证书域名 | 校验格式，支持泛域名与多域名 |
| 2 | acme.sh | 检查是否已安装 |
| 3 | DNS 插件脚本 | 检查 `dnsapi/<provider>.sh` 是否存在 |
| 4 | 凭据 1 | 检查是否已填写 |
| 5 | 服务商连通性 | **真实调用 DNS 服务商接口**验证凭据 |

### 连通性检测原理

acme.sh 没有独立的凭据校验命令，因此插件直接加载 acme.sh 与 DNS 插件脚本，调用其 `add` / `rm` 函数：

1. 向 `_acme-challenge-verify.<你的域名>` 写入一条测试 TXT 记录
2. 立即删除该记录
3. 两步都成功才判定凭据有效

测试记录使用固定的 `_acme-challenge-verify` 子域，**不会影响你的真实域名解析**。

### 检测结果示例

全部通过：

```
[OK] 证书域名: 共 1 个域名，格式正确
[OK] acme.sh: 已安装
[OK] DNS 插件脚本: dns_ali.sh 已就绪
[OK] 凭据 1: Ali_Key（AccessKey ID）已填写
[OK] 服务商连通性: 凭据有效，服务商连接正常
结论: 配置检测通过，可以申请证书
```

凭据错误时会给出排查方向：

```
[FAIL] 服务商连通性: 凭据验证失败：无法确认凭据有效性。常见原因：
① 凭据填写错误或已失效；
② 该凭据没有对应域名的 DNS 解析权限；
③ 域名未托管在当前 DNS 服务商。
```

> 部分服务商（如阿里云）在凭据错误时不会返回具体错误码，此时插件会给出上述通用排查建议。

## 凭据填写说明

插件把凭据拆成**两个独立输入框**，避免手写 `KEY=VALUE` 格式出错。填入的值会自动映射为 acme.sh 期望的变量名。

### 阿里云示例

| 输入框 | 填写内容 |
|---|---|
| 凭据 1 | AccessKey ID，形如 `LTAI5tExampleKeyId0000` |
| 凭据 2 | AccessKey Secret |

插件会自动转换为 `Ali_Key` 与 `Ali_Secret` 传给 acme.sh。

> 建议使用**只有 DNS 解析权限的子账号**密钥，不要用主账号密钥。

### 查询凭据字段

不同服务商需要的凭据字段不同，点击配置页的「**查询当前服务商需要哪些凭据**」按钮即可查看：

```
dns_cf 需要 5 个凭据字段

1. CF_Token
2. CF_Account_ID
3. CF_Zone_ID
4. CF_Key
5. CF_Email

按顺序填入下方两个输入框；
超过两个字段时，其余字段请写入脚本的 account.conf。
```

插件会**直接解析服务商脚本**得到准确字段名，因此覆盖 acme.sh 全部 198 个服务商。脚本尚未下载时会自动下载。

> 多数服务商只需 2 个字段，填入下方的两个输入框即可。部分服务商（如 Cloudflare、华为云）支持多种认证方式，会列出全部可选字段，按你使用的方式填写对应项即可。

## 服务商支持范围

**acme.sh 官方支持 198 个 DNS 服务商**，插件内置的只是常用快捷选项，**不是能力上限**。

### 使用内置列表以外的服务商

1. 在「DNS 服务商」下拉框中**直接输入**脚本名，如 `dns_xxx`
2. 点击「下载 DNS 插件脚本」，插件会从 acme.sh 官方仓库拉取
3. 点击「查询当前服务商需要哪些凭据」确认字段名
4. 按查询结果填写凭据输入框

### 手动确认凭据字段名

如需自行核对，可打开对应脚本搜索 `_readaccountconf_mutable`：

```bash
grep -E "_readaccountconf_mutable" /config/acme.sh/dnsapi/dns_xxx.sh
```

例如阿里云脚本输出 `Ali_Key` 与 `Ali_Secret`，所以凭据 1 填 AccessKey ID、凭据 2 填 AccessKey Secret。

> 未收录的服务商会使用通用字段名 `KEY1` / `KEY2`，此时需要手动确认脚本期望的变量名是否匹配。

### 查找脚本名

到 acme.sh 仓库的 `dnsapi` 目录查看完整列表：

```
https://github.com/acmesh-official/acme.sh/tree/master/dnsapi
```

## 前置条件

插件依赖 **acme.sh** 与 **openssl**。openssl 通常已随镜像提供，acme.sh 可**在插件界面一键安装**：

> 打开插件配置页，点击「**一键安装 / 升级 acme.sh**」按钮即可。
> 插件会从 acme.sh 官方仓库下载主脚本并创建所需目录，已安装时执行升级并保留原有账号与证书配置。

如需手动安装（例如离线环境）：

```bash
# get.acme.sh 直连可能被重置，改用 GitHub API
mkdir -p /config/acme.sh/data /config/acme.sh/dnsapi
curl -sL -H "Accept: application/vnd.github.raw" \
  "https://api.github.com/repos/acmesh-official/acme.sh/contents/acme.sh?ref=master" \
  -o /config/acme.sh/acme.sh
chmod +x /config/acme.sh/acme.sh
```

DNS 插件脚本同样可通过插件界面一键下载，无需手动操作。

> 插件会自动检测 acme.sh 与 DNS 插件是否存在，缺失时给出明确提示。

### 安装行为说明

| 场景 | 行为 |
|---|---|
| 未安装 | 下载主脚本，创建 `acme.sh`、`data`、`dnsapi` 目录结构 |
| 已安装 | 备份后升级到最新版，成功后删除备份 |
| 下载内容无效 | 自动回滚到原有版本，不会破坏正在使用的 acme.sh |
| 网络失败 | 返回明确错误提示，原有文件保持不变 |

## 配置项

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 启用插件 | 关 | 开启后才注册续期定时任务 |
| 发送通知 | 开 | 部署/申请/续期结果通知 |
| 续期检查周期 | `0 4 * * *` | cron 表达式 |
| acme.sh 目录 | `/config/acme.sh` | acme.sh 安装位置 |
| 证书部署目录 | `/config/certs/latest` | 证书文件输出位置 |
| 证书域名 | 空 | 多个用英文逗号分隔 |
| DNS 服务商 | 阿里云 | 可选择或直接输入脚本名 |
| 凭据 1 | 空 | Key / ID / Token |
| 凭据 2 | 空 | Secret / Token |
| 密钥类型 | EC 256 位 | 支持 EC 256/384、RSA 2048/4096 |

## 工作原理

### 手动部署流程

```
粘贴 PEM → 规范化换行 → 备份原证书 → 写入新证书
  → openssl 校验证书与私钥匹配 → 校验是否过期
  → 通过：重载 nginx ｜ 失败：回滚原证书
```

### 自动申请流程

```
校验域名/凭据 → 检查 acme.sh 与 dnsapi 脚本
  → 按服务商映射凭据字段名（如 Ali_Key / Ali_Secret）
  → acme.sh --issue --dns <provider> --domain <域名>
  → acme.sh --install-cert 输出到部署目录
  → 重载 nginx
```

### 自动续期流程

```
acme.sh --cron（内部按 ARI 窗口判断是否需要续期）
  → 读取证书剩余天数
  → 剩余 < 20 天：告警
  → 输出含 Cert success/Installing：重载 nginx 并通知
  → 其他：仅记录日志
```

## 通知说明

| 标题 | 触发条件 |
|---|---|
| 【证书管理】部署成功 | 手动部署完成 |
| 【证书管理】申请成功 | 自动申请完成 |
| 【证书管理】续期成功 | 续期完成并重载 nginx |
| 【证书管理】续期异常 | 续期后剩余有效期仍 < 20 天 |
| 【证书管理】执行失败 | acme.sh 不存在 |
| 【证书管理】执行超时 | 命令执行超过 600 秒 |
| 【证书管理】执行异常 | 无法启动外部命令 |
| 【证书管理】状态异常 | 无法读取证书有效期 |
| 【证书管理】重载失败 | nginx 校验或重载失败 |

未到续期时间时**不发通知**，避免每日打扰。

## 插件 API

| 路径 | 方法 | 说明 |
|---|---|---|
| `/status` | GET | 查询当前证书状态 |
| `/deploy` | POST | 手动部署证书，body 传 `cert` 与 `key` |
| `/issue` | POST | 自动申请证书，body 可选覆盖 `domain`、`dns_provider`、`dns_key`、`dns_secret` |
| `/renew` | POST | 立即执行一次续期检查 |
| `/dnsapi` | POST | 下载 DNS 插件脚本，body 传 `provider` |
| `/verify` | POST | 检测配置，body 可选覆盖 `domain`、`dns_provider`、`dns_key`、`dns_secret` |
| `/install` | POST | 一键安装或升级 acme.sh |
| `/credentials` | POST | 查询服务商需要的凭据字段，body 传 `provider` |

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示 `acme.sh 不存在` | 未安装 acme.sh | 点击配置页「一键安装 / 升级 acme.sh」按钮 |
| 提示 `缺少 DNS 插件` | 未下载对应 dnsapi 脚本 | 点击「下载 DNS 插件脚本」 |
| 提示 `服务商不存在` | 脚本名拼写错误 | 到 acme.sh 仓库确认正确脚本名 |
| 检测提示凭据无效 | 凭据错误或无权限 | 核对凭据，确认该凭据有域名 DNS 权限 |
| 提示 `证书与私钥不匹配` | 粘贴内容对不上 | 确认证书与私钥来自同一套 |
| 提示 `证书已过期` | 证书本身已过期 | 重新申请或更换证书 |
| 申请失败，提示凭据错误 | AccessKey 失效或权限不足 | 更新凭据 |
| 申请失败，提示变量未设置 | 凭据字段名与该服务商不匹配 | 查看脚本的 `_readaccountconf_mutable` 确认字段名 |
| 剩余有效期持续下降 | 续期未成功 | 查看 MoviePilot 日志中的 acme.sh 输出 |
| 通知未收到 | 通知渠道未配置 | 检查「设定 → 通知」 |
| 插件列表不显示 | 配置快照未刷新 | 重启 MoviePilot 进程 |

### 查看日志

```bash
# 插件执行日志
grep "证书管理" /config/logs/moviepilot.log | tail -20

# 查看证书有效期
openssl x509 -in /config/certs/latest/fullchain.pem -noout -subject -dates

# 查看线上实际生效的证书
echo | openssl s_client -connect 你的域名:端口 -servername 你的域名 2>/dev/null \
  | openssl x509 -noout -subject -dates
```

## 注意事项

1. **必须使用 DNS 验证**：容器内 80 端口通常由外部反代接管，HTTP-01 走不通。
2. **证书目录需与 nginx 配置一致**：MoviePilot 镜像默认使用 `/config/certs/latest/`，如你的 nginx 用其他路径，请同步修改插件配置。
3. **不要删除 `/config/acme.sh`**：其中保存 ACME 账号与 DNS 凭据，删除后需重新配置。
4. **多域名无需多插件**：一个 acme.sh 实例可管理多张证书，`--cron` 会续期全部。
5. **凭据安全**：DNS 凭据保存在插件配置中，建议使用最小权限的子账号密钥。
6. **未收录服务商**：使用通用字段名 `KEY1`/`KEY2`，需自行确认脚本期望的变量名。

# 隧道在线带宽让位（TunnelYield）

MoviePilot V3 插件。当"有人需要用网"时，自动为下载器让出上传带宽；用网结束后自动恢复。

两类触发源，任选其一或同时启用：

- **隧道主机监测**：配合采集端（装在 OpenWrt 路由器等隧道主机上），监控 EasyTier / WireGuard 组网内指定设备的在线状态——手机/平板一连上组网，下载器自动限速；
- [采集端源代码](https://github.com/RamenRa/MoviePilot-Plugins/tree/main/file) ，下载“采集端源码打包版.zip”安装，不知道如何安装将readme.md提交给AI提问即可。
- **Jellyfin/Emby 播放监测**：不使用采集端，直接复用 MoviePilot 中已登记的媒体服务器——外网设备开始看视频，下载器自动让位。

**让位动作**（二选一）：暂停下载器中有上传流量的任务，或开启全局限速（限速值可自定义）。

**恢复**：全部来源都不需要让位后，自动恢复本插件暂停的任务、还原限速原值。只恢复插件自己暂停的，你手动暂停的任务不受影响。

## 第一部分：使用指南（面向用户）

### 一、我该用哪种触发源？

| 你的场景 | 推荐 |
| --- | --- |
| 家人用平板/手机连 VPN/组网回家看视频、NAS 远程访问 | 隧道主机监测 |
| 家人在外面用 Jellyfin/Emby 看视频，占满上传带宽导致你想看的资源缓冲 | Jellyfin/Emby 播放监测 |
| 两种都有 | 同时开启，任一触发即让位（"或"关系） |

两个来源共用同一套让位/恢复逻辑和下载器记录，互不干扰。

**只用播放监测的极简配置**：监控主机列表留空、连接与认证全部留空、勾选下载器、打开"监测 Jellyfin/Emby"即可。隧道相关的密钥、地址、心跳等参数留空都有短路保护，不会报错。

### 二、让位方式怎么选？

| | 暂停上传任务（默认） | 全局限速 |
| --- | --- | --- |
| 效果 | 上传完全停止（0 带宽） | 保留限速值内的上传（如 512 KB/s） |
| 恢复后 | 任务继续做种，无残留 | 原限速值还原，无残留 |
| 开销 | 在线期间每次巡检要拉取种子列表，种子越多越慢 | 恒定微小程序，与种子数无关 |
| 适合 | 种子量 < 2000，追求彻底让位 | 种子量大，或只想"留一口气" |

暂停方式只暂停**正在上传**的任务；空闲做种的任务不动，等它开始传了，下一次巡检再补暂停。

### 三、配置项逐项说明

#### 基本设置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用插件 | 关闭 | 停用时会自动恢复插件暂停的任务、还原限速 |
| 上线通知 | 开启 | 控制主机上线通知和播放开始通知；两类通知独立冷却（各 1 小时最多 1 次），关闭不影响让位动作 |
| 立即检测一次 | 关闭 | 保存后 3 秒执行一次完整检测，执行后自动复位。用于配置完验证 |

#### 连接与认证（隧道功能用；只用播放监测可全留空）

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 检测方式 | Webhook推送 | 采集端每 2 秒采集、变化时推送（推荐，秒级响应）；轮询由插件定时查询采集端。**必须与采集端 `WORK_MODE` 一致**，选错不会坏数据但功能不生效 |
| 通信密钥 | 空 | 推送与查询共用的同一个密钥，与采集端 `SECRET` 完全一致（首尾空格也算不一致）。为空时拒绝所有推送 |
| 采集端 API 地址 | 空 | 轮询必填，格式 `http://<采集主机IP>:<端口>/`；推送模式选填，填了才启用心跳兜底与启动同步 |
| API 超时 | 10 秒 | 查询超时 ≠ 离线，保持现状不动 |

#### 调度与失联保护

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 检测/补偿周期 | `*/1 * * * *` | 轮询模式=查询采集端的周期；推送模式=巡检周期；播放监测也沿用这个周期做兜底扫描（见下） |
| 主动心跳间隔 | 300 秒 | 仅推送模式且填了 API 地址时生效。每 300 秒主动查一次采集端防止漏推，0 关闭 |
| 采集端失联释放 | 60 分钟 | 超过该时长没收到采集端任何消息（推送/保活/心跳/轮询都算），判定采集端宕机，**撤销插件对下载器的全部操作**，避免下载器无限期暂停。0 关闭；最小 30 分钟（必须大于采集端 25 分钟的保活间隔）。这是超时保护，不代表主机离线——采集端恢复后会按最新状态重新判定 |

**播放监测的周期**：在 Jellyfin/Emby 中配置了 MoviePilot 的 Webhook 时，播放开始/停止秒级触发检测，本参数只是兜底，`*/5 * * * *` 足够；没配 Webhook 时它是唯一发现手段，保持 `*/1`。

#### 监控与下载器

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 下载器 | 空 | 可多选 qBittorrent。取消勾选且有未恢复记录的下载器，在线期间继续让位、离线恢复后解除管理 |
| 监控主机列表 | 空 | 隧道内设备的虚拟 IP 或主机名，每行一个，`#` 后为注释，支持 `IP,主机名` 同行写法。**不要填采集端本机节点**（如 EasyTier 的 Local 行，恒在线，会导致永久让位） |

#### Jellyfin/Emby 播放监测

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 监测 Jellyfin/Emby | 关闭 | 自动使用 MoviePilot 媒体服务器设置里已登记的 Jellyfin/Emby，**不需要另填地址和密钥**；不受监控主机列表影响 |
| 不限速地址范围 | 空 | 单个 IP、CIDR 网段或 `起始-结束` 区间，逗号分隔。**留空默认排除内网/本机/链路本地地址**——家里设备播放不会触发让位；填写后默认排除失效，只按你填的排除。**注意**：设备若经 EasyTier/Tailscale 访问，`RemoteEndPoint` 可能是 `100.64.x.x`（会被默认排除而让位不生效），需要显式填规则把隧道段排除、但把真正要监控的设备地址留出来 |
| 不限速路径 | 空 | 播放文件路径包含任一行即不让位，每行一个（如 `/media/音乐`），兼容 Windows 路径 |

播放判定三要素：**视频**（音频不算）、**未暂停**、**地址和路径未被排除**。查询媒体服务器失败 ≠ 无播放：若此前确认在播放，保持让位最长 30 分钟，超时后不再阻止恢复。

#### 带宽让位策略

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 让位方式 | 暂停上传任务 | 二选一 |
| 上传限速 | 512 KB/s | 限速方式专用；0 = 上传不限速（等于没让出带宽） |
| 下载限速 | 0 | 限速方式专用；0 = 下载不限速 |

### 五、验证配置是否生效

1. 打开"立即检测一次"保存，详情页应出现状态卡片
2. 触发源测试：让监控设备连上组网 / 用外网设备播放一个视频
3. 观察：下载器对应任务暂停或限速生效，收到通知
4. 结束后：任务恢复、限速还原（限速方式可用下载器界面核对原值）
5. 详情页"运行阶段"应显示 `Jellyfin/Emby 播放中` 或 `让位维护中`

### 六、常见问题

**播放了却没有让位？**
- 详情页"Jellyfin/Emby 播放监测"卡片看设备 IP——若落在 10.x / 100.64.x 等默认排除段，在"不限速地址范围"里显式填规则
- 确认不是音频（只有视频触发）
- 确认 MoviePilot 媒体服务器设置里登记了这台 Jellyfin/Emby（表单配置区会显示"当前已登记：xxx"）

**暂停的任务一直没有恢复？**
- 看详情页运行阶段：`采集端失联…` → 等采集端恢复，或确认失联释放已触发
- `N 个暂停待确认` → 暂停请求结果未知的记录，插件有意不自动恢复，需手动核对
- 隧道主机离线但家人还在看视频 → 设计如此，播放结束后才恢复

**想把某些资源排除（家人看动画片不想让位）？**
用"不限速路径"，填媒体库路径即可。

**暂停方式响应慢？**
新开始上传的任务要等下一个巡检周期才被暂停，调小"检测/补偿周期"；种子量几千以上建议换限速方式。

### 七、性能与调优

- 稳态（全部离线且恢复完毕）**零下载器访问**；采集端侧每 2 秒一次 CLI，开销恒定
- 在线期间唯一周期负载是巡检：**暂停方式约 0.25~0.7 秒/1000 种子**（瓶颈在 qBittorrent 生成 API，不读磁盘；机械硬盘不改变平均值，但 qBT 忙时单次调用可能数秒）；**限速方式恒定 5~15 毫秒，与种子数无关**

| 种子数量 | 建议巡检周期 |
| --- | --- |
| < 1000 | `*/1 * * * *` |
| 1000~3000 | `*/2 * * * *` |
| 3000~10000 | `*/5 * * * *` |
| 限速方式 | 任意周期，开销恒定 |

## 第二部分：采集端部署指南

仅隧道主机监测需要。采集端运行在能执行隧道命令的主机上（OpenWrt 路由器、跑 EasyTier 的 NAS/VPS），把节点状态转成统一快照推送给插件。

### 部署前准备

- EasyTier：知道 `easytier-cli` 的绝对路径；WireGuard：已安装 `wireguard-tools`
- MoviePilot 的 API_TOKEN（设置 → 安全 → API密钥）
- root 权限、交互终端；Python 3.8+；Ubuntu/Debian 需运行中的 systemd，不支持普通 Docker/WSL
- `tunnel_api.py` 和安装脚本放同一目录，脚本不从互联网下载代码

### 安装

```sh
# Ubuntu / Debian
sudo sh "Tunnel API_install.sh"
# OpenWrt（root SSH）
sh "Tunnel API_install.sh"
```

安装器交互询问：工作方式（webhook 推荐 / poll）、采集驱动（easytier / wireguard / jellyfin）、CLI 路径、Webhook 地址、API_TOKEN、通信密钥（自动生成）、监听地址端口（默认 `0.0.0.0:8080`）、采集间隔（默认 2 秒）、保活间隔（默认 300 秒）。安装完成后**在终端输出一次 MoviePilot 需要填写的全部参数**（含当前节点列表供挑选监控主机）。

安装位置：Ubuntu/Debian `/opt/tunnel-api/`，OpenWrt `/etc/tunnel-api/`；配置 `config.json`（600）与 seq 状态文件 `tunnel_api_state.json`（**不要删除**）；服务名 `tunnel-api`。

### 管理命令

```sh
# Ubuntu / Debian
sudo systemctl status tunnel-api
sudo journalctl -u tunnel-api -f
sudo systemctl restart tunnel-api
# OpenWrt
/etc/init.d/tunnel-api status
logread -e tunnel
/etc/init.d/tunnel-api restart
```

修改 `config.json` 后必须重启服务。长期停止采集服务前，先在插件侧停用或处理好让位。

### 工作方式对照（两侧必须一致）

| 插件检测方式 | 采集端 WORK_MODE | 必填 |
| --- | --- | --- |
| Webhook推送（推荐） | `webhook` | 通信密钥、监控主机 |
| 轮询 | `poll` | API 地址、监控主机 |

### 故障排查

- **推送一直失败**：先查 MoviePilot 日志是否提示密钥不符 → 核对 SECRET 一致；再查插件是否启用、检测方式是否 Webhook推送；最后 curl 验证网络连通
- **推送成功但无动作**：插件日志搜"推送已接收但未应用"（seq 回退，多为多采集器并存，只留一个）；检查下载器勾选和监控主机；检查是否误填采集端本机节点
- **显示"上次检测失败，保持现状"**：隧道服务挂了/CLI 路径错/输出格式变，查采集端日志
- **WireGuard 客户端在线却离线**：客户端 `[Peer]` 加 `PersistentKeepalive = 25`
- **下载器被暂停一直不恢复**：确认采集端还在运行（失联释放需等待时长），看详情页运行阶段

## 第三部分：运行原理（供 AI/进阶用户查阅）

> 本节描述插件内部机制。把本 README 交给 AI 时，本节可让 AI 准确回答"为什么这样设计""某个现象是否正常"类问题。

### 整体架构

```
隧道主机(采集端) --状态变化推送--> 插件核心 --在线?--> 让位：暂停上传 / 全局限速
      |                                |
      +--每300秒保活重推（兜底丢包）------+--补偿检查：在线期间补暂停新上传任务、重试失败操作
                                            （离线恢复不由它驱动，由快照即时驱动）
Jellyfin/Emby（MP内置）--播放Webhook/周期查询--^  与隧道判定是"或"关系
```

**保活**：采集端每 300 秒重发完整状态。防推送丢失（插件重启/网络抖动），也是插件判断采集端存活的依据。
**补偿检查**：仅在线期间按周期扫下载器。恢复动作不依赖它——主机离线的推送一到立即恢复，补偿只负责"在线期间新上传任务补暂停"和"失败操作重试"。
**失联释放**：`max(最近联络时间, 本轮启动)` 起算，超 `lost_release` 分钟无有效快照 → 判定采集端宕机，撤销全部让位、判定置 `lost`，采集端恢复后按新快照重新判定。播放中的话保留让位，播放结束再恢复。
**播放监测**：查询在类级锁外执行（慢 HTTP 不阻塞隧道检测），用"配置代次 + 单调时钟"双闸防乱序；`sessions` 三态语义——有播放（任一服务器有即让位）、空列表（确认无播放）、`None`（查询失败≠无播放，保持让位最长 30 分钟）。

### 保护机制

1. 查询失败 / 推送格式异常 / 密钥不符 ≠ 离线，一律保持现状
2. 任一主机在线或有播放即保持让位；全部明确离线且无播放才恢复
3. 只恢复本插件暂停的任务：暂停意图先落盘 `pending_hashes`（崩溃安全），停止成功才归属 `paused_hashes`；恢复后读回确认
4. 限速先读原值落盘再修改，还原后读回一致才清除快照；读取失败返回 `None` 绝不当作"不限速"
5. 快照 `seq` 单调递增判序：旧版本拒绝；同 seq 同内容按重同步；同 seq 不同内容拒绝
6. 补偿检查三重授权：本轮已同步 + 判定绑定的监控列表未变 + 判定未过期（max(心跳×2, 1800) 秒）
7. 双重认证：宿主层 `X-API-KEY` + 插件层 `X-Tunnel-Secret`（常数时间比较，空对空不放行）
8. 暂停请求结果无法确认（异常）→ 保留为"待确认"，**有意不自动恢复**，只提示一次
9. 状态写盘节流：内容不变不写；仅时间戳类字段变化最多每 600 秒写一次
10. 多下载器独立记录（`downloaders[name]`），单台异常隔离；记录绑定下载器标识，换绑后在线继续让位、离线恢复原下载器

### 状态机与判定规则

隧道判定 `decision`：`online` / `offline` / `unknown`（存在未知状态主机）/ `lost`（失联释放）/ `None`（未同步）。
监控匹配：配置项与快照条目的 IP（去前缀长度）或 hostname **完全相等、区分大小写**；首个匹配的配置项成为该主机的稳定身份（IP 更换不重置通知冷却）。
通知：上线边沿检测 + 每主机独立冷却 3600 秒；离线不通知；仅发送成功才消耗冷却。

### 推送协议（第三方采集端）

- `POST /api/v1/plugin/TunnelYield/webhook`，请求头 `X-API-KEY`（MP API_TOKEN）+ `X-Tunnel-Secret`（通信密钥）
- 报文：`{"schema":1, "source":"easytier", "seq":<正整数>, "timestamp":<秒>, "peer_list":[{"ipv4":"10.100.0.2/24","hostname":"x","is_online":true}, ...]}`
- `seq` 必填、重启不回退（号段持久化预留）；`is_online` 必须 JSON 布尔；`peer_list` 非空且包含全部已知节点（离线者 `false`；空列表按失败处理）
- 响应 `{"success":true/false,"message":...}`；送达 = HTTP 200 且 `success` 严格为 true；`success:true` 只表示已接收不一定已应用（seq 回退等情形 message 不同）

### 适配扩展

- **新隧道类型**：采集端继承 `TunnelProvider` 实现 `collect()`（失败返回 `None`，绝不用"全部离线"冒充），登记到 `PROVIDERS`，复用 seq/保活/推送/查询公共流程
- **新下载器**：插件侧继承 `DownloaderAdapter` 实现 5 个方法（`list_torrents/pause/resume/read_limits/write_limits`，失败返回 `None`/抛异常），登记到 `DOWNLOADER_ADAPTERS`

### 已知限制

- 下载器适配器仅内置 qBittorrent；媒体监测仅 Jellyfin/Emby
- 播放监测不判断会话新鲜度（`LastPlaybackCheckIn`），客户端崩溃遗留的僵尸会话可能短暂误报
- 无法识别的媒体类型按"不播放"跳过（不升级为查询未知）
- Webhook 推送依赖 MoviePilot V3 插件动态 API；旧版主程序请用轮询模式
- poll 工作方式与部分保护策略经模拟测试验证，未在真实环境全量回归

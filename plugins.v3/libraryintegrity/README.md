# 影视库完整性检查

检查影视库的缺集、同季版本不一致与多文件问题，结果以报告形式展示。数据来自 Emby 或插件直接扫描的
本地目录。插件只读取 Emby、本地文件、NFO 与 TMDB 数据，不修改、不删除任何文件，也不会自动订阅或洗版。

## 检查内容

| 分类 | 说明 |
| --- | --- |
| 缺集 | 与 TMDB 已播出的集比较（播出超过缓冲天数才计入），默认不查第 0 季 |
| 版本偏离 | 每季以多数版本为基准，报告分辨率、编码、HDR 等偏离的单集；没有多数时报告分布 |
| 多文件 | 同一集或同一电影有多个版本，或多个条目指向同一集/同一电影 |
| 编号冲突 | 每季一条：库内季集号在 TMDB 中不存在、缺少季集号，或 NFO 与 Emby 记录的季集号不一致；附处理提示 |
| 无法核对 | 没有 TMDB ID、TMDB 查询失败或单集读取失败的剧集，表示未检查而不是没有问题；库内编号与 TMDB 不一致的剧也归入此类，不直接报告缺集 |
| AI 建议 | 已通过规则验证、等待采纳的编号映射或身份建议（需启用 AI 建议） |

## 数据来源

- **Emby**：使用 MoviePilot 中已配置的 Emby，插件不单独保存地址和密钥。读取单集的单集 TMDB ID、
  媒体流与多版本信息；读取 NFO 时如 Emby 与 MoviePilot 看到的路径不同，需配置路径映射。
- **本地目录**：不经过媒体服务器直接遍历，适合没有加入 Emby 的目录。建议只填写 Emby 未覆盖的目录，
  避免同一内容被报告两次。
  - 剧集身份依次取自 `tvshow.nfo`、目录名中的 `{tmdbid=…}` 标记、MoviePilot 整理记录。
  - 单集文件按文件名中的季集号识别。季目录包括 `Season 1`、`S01`、`第一季`、`Specials`，含 `season.nfo`
    的目录，以及剧集目录下自定义命名的子目录（如「立志篇」）；`extras`、`trailers` 等目录会跳过。
  - 同一 TMDB 剧集分散在多个目录（如改名前后各存一份）时合并核对，同一集的多个文件作为多个版本。
  - 有 `tvshow.nfo` 但还没有任何单集文件的剧也会核对，整季未下载会报告缺集。
  - strm 只读取文件内的地址字符串用于解析文件名，不会请求远程文件。
  - 可选读取本地视频的媒体信息（优先 `ffprobe`，其次 `mediainfo`，MoviePilot 官方镜像自带 `ffprobe`）。
    结果按文件大小和修改时间缓存，未变化的文件不再读取；每轮新读取的文件数有上限，其余留到下一轮。

## 判定方式

- **按单集 TMDB ID 匹配**：MoviePilot 刮削的单集 NFO 记录了该集自己的 TMDB ID，Emby 读取后保存在
  ProviderIds 中。插件优先按单集 ID 对比，不受剧集组、绝对集数等编号差异影响；缺少或无效的单集 ID
  （包括旧版 NFO 误写的剧集 ID）才回退到按季集号匹配，并应用已采纳的编号映射。
- **版本信息来源**（按可信度）：Emby 媒体流或本地媒体信息 → Emby 生成的 NFO 中的 streamdetails →
  文件名 → strm 内地址中的文件名。取不到的维度记为未知，不参与比较。

## AI 建议

需要在系统设置中启用智能助手，并在插件中开启「启用 AI 建议」。AI 只提出假设，不直接判断缺集：

- **编号映射**：剧集存在按季集号无法对应的单集时（如动画按绝对集数编号），AI 提出
  `库内 S1E13-E24 对应 TMDB S2E1 起` 这样的映射。只有能减少无法对应的集数、且不会让多个条目撞到
  同一集的映射才会出现在报告中。
- **身份选择**：剧集缺少 TMDB ID 时，插件先在 TMDB 搜索候选，AI 只能从候选中选择。只有库内至少 80%
  的单集能在所选剧集中按季集号找到对应时才会出现在报告中。
- **报告摘要**：可选，附在通知和报告页顶部。

调用次数不设上限。在报告页点击「采纳」会把建议写入「编号映射」或「身份指定」规则，之后的扫描直接
按规则执行，不再调用 AI；点击「忽略」后该范围不再请求 AI。标题、文件名等数据作为不受信任的内容
传给模型，模型输出必须符合固定结构并经过上述验证。

## 规则

- **忽略规则**：每行一条，格式 `[类型@]tmdb:ID[:S季[E集]]`，类型可选 `missing`、`version`、
  `duplicate`、`conflict`、`unchecked`、`suggestion`。
- **编号映射**：`tmdb:ID S1E13-E24 => S2E1`。
- **身份指定**：`emby:服务器/条目ID => tmdb:ID` 或 `local:目录 => tmdb:ID`。

```text
tmdb:1399                    # 忽略整部剧的全部问题
missing@tmdb:1399:S0         # 只忽略第 0 季的缺集
version@tmdb:1399:S2         # 只忽略第 2 季的版本偏离
duplicate@tmdb:1399:S1E5     # 只忽略 S01E05 的多文件
```

## 数据保存

扫描报告保存在插件数据目录的 `report.json`，TMDB 季集与本地媒体信息的缓存也在该目录。
旧版本保存在插件数据表中的报告会在插件启动时自动迁移。

## 接口与智能助手

接口均需登录（`bear`），返回 `{success, message, data}`：

- `POST /api/v1/plugin/LibraryIntegrity/scan`：立即扫描一次。
- `POST /api/v1/plugin/LibraryIntegrity/ignore`：添加忽略规则，请求体 `{"key": "tmdb:1:S1", "type": "missing"}`。
- `POST /api/v1/plugin/LibraryIntegrity/adopt`：采纳规则，请求体 `{"kind": "mapping", "rule": "tmdb:5 S1E13-E24 => S2E1"}`。
- `GET /api/v1/plugin/LibraryIntegrity/report`：最近一次报告及应用忽略规则后的问题。

插件启用时向智能助手注册只读工具 `query_library_integrity`，可以直接询问「哪些剧缺集」
「某部剧的版本是否一致」等问题。该工具只读取最近一次报告，不会触发扫描或修改规则。
